# 状态文档维护

当前状态是交接手册；机制写专项手册，交付/排查写[台账](../../../../docs/history/README.md)，完整流水从Git历史读取。

## 读取与事实

定位git根、分支/提交及工作树，保留无关改动。只读本次相关章节；整体重排时完整UTF-8读取，PowerShell显式-Encoding UTF8。区分仓库目标、在线观测和历史证据，观测日期为Asia/Shanghai；纯文档整理不刷新事实日期，不把过期“下一次”写成未来。

## 当前状态必需项

保留当前目标、运行架构、已具备能力、现役配置/安全、部署与回退、仍需处理、长期不变量及简短验收。当前值仅一处维护；旧镜像/已解决问题移台账，冲突按较新真实证据替换。只有已闭环才删除待办。

## 小功能与bug记录

- 默认更新现行手册及一条台账，通常3–5行：日期、变化/根因、最终验证、必要回退/未决事项。
- 只留最终一次验收结论；已通过检查复用，仅新改动、失败或具体未决问题才补验。不逐项记录提权、脚本迭代、任务轮询和重复测试数量，不新建长日期报告/证据包。
- 一次性过程按提交/脱敏外部路径追溯。AI冻结题集、原始评分/回答、数据快照、必要恢复证据保留原字节。
- SQL/迁移、安全/许可、难回退事故保留必要范围、检查点、限制；业务通过不关闭安全风险。

## 证据与边界

结论写适用日期、服务/版本、功能/入口结果及具体未决项。代码、配置、上线、业务结果、真实登录/外部出站、人工质量、任务注册/运行和备份/恢复分别成立。一次性ID只留交接所需，凭据、原日志、完整SQL/provider正文不进docs。

资源repair按ID/provider核NORMAL/自有URL/可选GYING；QQ核开关/目标/官方结果；OpenClaw核源/唯一runtime/UTF8/白名单。只验证本次影响范围，不为更新文档制造副作用。UNKNOWN不重放，NapCat不恢复，原授权不延伸新操作范围。

## 检查与同步

授权分支与实际部署分别标明；只同步相关文档/Skill，不自动合业务。小交付验收后只更新相关章节，纯文档只检查UTF8、链接/引用、事实矛盾、敏感字段和diff，无需运维快照或上线。
