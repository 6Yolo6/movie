# 部署与恢复

按任务读取唯一维护的流程，避免复制旧命令：

- 已有环境增量、候选构建、固定镜像、最小替换、入口验收和回滚：[部署与回滚](../../../../docs/deployment.md)。
- 新服务器、跨主机迁移、隔离恢复与数据切换：[迁移手册](../../../../MIGRATION.md)。
- 加密清单、认证解密和恢复门禁：[备份方案](../../../../docs/security/backup-plan.md)。
- 空库/存量库与大小写来源身份：[数据库](../../../../docs/database.md)。
- 发布在途记录及联动版本：[发布运维](../../../../docs/social-publishing.md)。

## 执行时不能省略的判断

1. 完整读取[当前状态](../../../../docs/current-project-status.md)，区分历史证据与本次需验证事实。仅文档任务不触发部署/恢复。
2. 用 `git rev-parse --show-toplevel` 确认检出位置，核对主机、提交、工作树和维护窗口，运行本 Skill 的快照与就绪脚本。
3. 显式使用现役项目 `-p gying-movie`、生产 Compose 和经审查覆盖文件。现役运行配置与仓库目标不一定相同；不能通过一次全栈 up 顺带加固。
4. 固定候选与旧镜像，保留运行参数、实际卷名/挂载和仓库外加密备份。发布恢复至少核对两个发布状态卷和 MySQL 审计，不只 QQ 账号目录。
5. 协调相关写入方和在途副作用；新/恢复环境先关闭自动化。不能批量重置 RUNNING/UNKNOWN，也不以手工真实帖子作为默认健康探针。
6. 仅替换受影响服务，nginx 测试后平滑重载。先核验实际镜像、内部依赖/SSR，再验本机/公网入口与日志；未改服务相对原有基线核对，不要求历史重启计数清零。
7. 状态机变更时 backend/publisher 协调部署/回退；应用回滚保留 `utf8mb4_bin`。数据/外部副作用不兼容则停止自动回退，不能用旧 dump 覆盖新数据。
8. 门禁 FAIL、测试失败或目标不清时停止相应动作并汇报；历史部署不代表风险关闭或授权可复用。

NapCat 已停用，不恢复、不启动。OpenClaw、宿主机频道任务与独立发布器是不同链路，必须分别盘点。真实账号登录、转存、发布和删除需要明确范围，不因恢复任务自动获得授权。

完成后按[状态维护](status-maintenance.md)只更新经过验证的变化；测试、候选、部署和真实副作用证据分开，历史材料从[历史导航](../../../../docs/history/README.md)引用。
