## 修复内容

### 热门榜与通知页

- 热门榜按查询／请求身份隔离结果，取消过期请求，并在传输层忽略取消或 JSON 解析延迟时阻止旧结果覆盖。请求失败显示持久错误及重试，不再伪装为成功的空榜单。
- 通知记录与总数绑定当前账号、分页和未读筛选；不同查询失败时不残留上一组记录，同查询刷新失败保留已有内容。切换账号、卸载后的迟到结果不更新页面。
- “全部已读”完成后通过当前 effect 刷新第一页，不再调用捕获旧页码的刷新函数；末页缩减时回退有效页；固定每页 20 条。
- 热门榜只新增一组中英文失败文案。没有重新设计其他页面或修改发布状态机。

### 后端查询边界

- 影片搜索的 SQL 统计、Redis 热词计数及资源查看统计分别作为非关键旁路处理。它们抛出运行时异常时不再中断已成功的查询；仅记录固定操作名与异常类型，不写异常正文、堆栈或请求数据。真实查询失败和通知更新失败仍向调用方抛出。
- 资源列表保持当前影片、审核通过、`ACTIVE` 条件，增加 `deleted_at IS NULL`，并使用带括号的 `(link_status IS NULL OR link_status <> 'INVALID')`。测试检查实际生成 SQL 与参数，避免 `OR` 绕过归属、审核、软删条件。
- “全部通知已读”改为一次带 `user_id = 当前认证用户 AND read_flag = false` 条件的 SQL 更新，返回实际影响行数；不再全量加载实体。空用户 ID 不执行 SQL。当前通知表没有 `deleted_at`，不添加不存在的字段，也不按目标内容的删除状态联动过滤。
