## 3. 学习知识如何落到项目

| 知识 | 项目练习 | 面试要解释的取舍 |
| --- | --- | --- |
| SQL、事务、唯一约束 | 外部来源身份、发布认领、关联迁移和幂等写入 | 数据库本地原子性与远端副作用之间的确认空隙 |
| 并发、线程池、截止时间 | 单模型并发、独立续期线程、180/240秒预算、优雅排空 | 超时何时停止等待，何时不能立即终止已发送请求 |
| HTTP与鉴权 | 同域API、JWT/设备吊销、固定loopback工具、Access和Redis限流 | 客户端状态不替代服务端权限；边缘与源站各自保护什么 |
| 信息检索 | BM25、归一向量内积、RRF、候选相关性和硬条件 | 召回与排序分开；相似度不是正确性；可核验字段不能交给相似分决定 |
| Agent与Harness | Schema、上下文、job/attempt/lease/checkpoint/trace | 结构化查询流程与自由工具循环不同；恢复回执不是续算所有步骤 |
| 评测与实验 | 同源分组/freeze、人工标签、严格配对、冷温与负载记录 | 请求完成率、Recall和人工需求命中是不同指标 |
| 运维与安全 | 固定镜像、最小切换、加密备份/认证、Git与运行态对照 | 有备份不等于已恢复；测试通过不等于安全风险关闭 |

Python用于评测和数据脚本，Java继续承载主要业务；先理解JSON Schema、原生工具调用和边界，再映射框架抽象。项目其他知识点按[全项目知识导读](project-guide.md)逐项查看源文件。

## 5. 演示与面试提纲

按一个连续场景演示：用户提出条件 → 展示实际queryPlan与候选 → 追问第N部 → 展开资料与联网轨迹 → 展示同回执重复确认测试 → 展示一条偏题或条件误解析及改进路线。

准备回答：为什么只有简单问题直接分流；为什么模型不能写SQL；为什么使用RRF；怎样防旧向量和旧lease；为什么HTTP200仍会失败；什么时候能重试；为什么短窗口成功不是长期可用性；怎样证明候选有用而不是只证明请求完成。

原30题保持冻结且已被观察，原评测输出不改写。新题按sourceGroup划分，避免同一题的改写跨训练/开发与留出集合；人工标注与模型评判分开。企业演示只用合成公开数据，不引入公司人员资料、内部源码或秘密。
