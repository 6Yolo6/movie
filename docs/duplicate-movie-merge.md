# 重复影片审核与合并

[Resource Hub](resource-hub.md) · [接口](api.md#重复候选审核与合并) · [数据库](database.md) · [实际状态](current-project-status.md)

## 页面流程

后台 Resource Hub 的“全库扫描重复”完成后，管理员勾选候选并选择每组保留的影片 ID，点击“预览合并”，查看关联影响与阻断原因，逐组确认后点击“一键合并”。候选来自名称、年份、类别、季数与来源核对，仍需要人工确认；不默认全选。每批最多 20 对，每个影片 ID 在同批仅能出现一次；扫描不完整时不能合并。

预览有效期十分钟，属于创建它的管理员。执行前再次锁定并核对元数据、关联和表结构；任何变化使整批返回 409，重新预览后再确认。整批同一事务，不留下部分成功。同一成功审核使用原 UUID 幂等键可回读结果。网络响应未知时页面锁定原选择，允许明确使用原键重试。

## 保留规则

- 保留目标影片，软删除源影片，并建立永久旧 ID 别名。链式合并展平到最新目标；旧详情、资源和收藏请求仍解析到保留项。
- 迁移资源、来源身份、发现结果、三盘任务与精确清理任务引用、操作/QQ/发布日志、普通影片评论和 MOVIE 类型通知。只迁移对应影片 ID，保留其他字段、状态和时间。
- 收藏冲突先保存完整原行历史，再去重；所有关联保存迁移前摘要。目标资源状态按正常、已审核且非临时 DISK 视频分享刷新，其他元数据和更新时间保持。
- 活跃、UNKNOWN、待确认副作用、临时 scope/清理绑定、来源身份冲突、续集/季数矛盾、未知关联表或唯一约束冲突阻断执行，页面显示原因。
- 迟到写入通过数据库保护解析旧 ID；无法安全改写的运行 payload 拒绝写入。父任务的不可变 `deferredItems` 审计保留原身份，不当作待消费引用。

合并只整理本库记录与引用，不删除网盘文件或重放未知任务。上线验收使用隔离真实 MySQL 执行合并，生产仅做全库只读扫描与预览；管理员后续实际确认才执行生产合并。

## 部署与恢复

新增四张审核/别名/历史表及 34 个 BEFORE INSERT/UPDATE trigger。维护身份先核对原库、正常停止旧后端并完成加密 SQL/配置/镜像/状态备份，再按实际缺失定义执行两份增量 SQL。MySQL 8.0.28 不支持带 IF NOT EXISTS 的 CREATE TRIGGER，已有同名定义必须精确匹配，不能覆盖。

新别名或百度 UNKNOWN 待审进度存在后，旧消费者不能直接回退；保留在线 SQL、会话、原任务和检查点，优先兼容的前向修复。禁止用旧 dump 覆盖新增历史或删除新表作为回退。
