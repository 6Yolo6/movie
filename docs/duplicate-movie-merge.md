## 页面流程

后台 Resource Hub 提供直接可见的“一键去重”按钮：读取全库候选的全部分页，仅预选名称与人物共同支持（`NAME_AND_PEOPLE`）且影片 ID 未出现在其他候选组中的记录，按每批最多 20 对预览关联影响，剔除被后端阻断的组，并重新预览可执行子集。确认窗口列出合并方向、双方资源数量、关联影响及跳过原因；管理员核对全部记录并确认后，依次执行各批。人物重合与安全检查通过仍需管理员确认同片身份，不直接授权合并。

原“扫描全库重复影片”入口保留：管理员自行勾选候选、选择每组保留的影片 ID，点击“预览合并”，逐组确认后点击“一键合并”；该路径不默认全选，仅名称匹配（`NAME_ONLY`）及涉及多个候选组的记录继续使用人工流程。扫描不完整、分页数量变化或候选缺失/重复时，一键去重停止准备。每个影片 ID 在同批仅能出现一次。

预览有效期十分钟，属于创建它的管理员。执行前再次锁定并核对元数据、关联和表结构；任何变化使该批返回 409，重新预览后再确认。每批同一事务，不留下该批内部的部分成功；一键去重的各批独立提交，后续批次过期、变更或失败时停止，页面保留已完成数量。同一成功审核使用原 UUID 幂等键可回读结果。网络响应未知时页面锁定原选择，允许明确使用原审核与原键重试，不自动发起新合并。

## 保留规则

- 保留目标影片，软删除源影片，并建立永久旧 ID 别名。链式合并展平到最新目标；旧详情、资源和收藏请求仍解析到保留项。
- 迁移资源、来源身份、发现结果、三盘任务与精确清理任务引用、操作/QQ/发布日志、普通影片评论和 MOVIE 类型通知。只迁移对应影片 ID，保留其他字段、状态和时间。
- 收藏冲突先保存完整原行历史，再去重；所有关联保存迁移前摘要。目标资源状态按正常、已审核且非临时 DISK 视频分享刷新，其他元数据和更新时间保持。
- 活跃、UNKNOWN、待确认副作用、临时 scope/清理绑定、来源身份冲突、续集/季数矛盾、未知关联表或唯一约束冲突阻断执行，页面显示原因。
- 迟到写入通过数据库保护解析旧 ID；无法安全改写的运行 payload 拒绝写入。父任务的不可变 `deferredItems` 审计保留原身份，不当作待消费引用。
- 夸克旧流程成功后仍可能保持 `SUBMITTED`。只有已完成、无错误和不确定节点、非临时任务，并且任务→发现结果→已审核正常资源的自有分享 URL、hash 与验证时间全部一致时，才按已完成引用审核；证据行一起锁定并纳入快照。其他 provider 的 `SUBMITTED` 仍阻塞。
- P2P 归档的根 `mid/typeCode` 是 GYING 来源身份。仅已结案、已知版本和 provider、`mid` 等于本次保留目标且任务属于该目标时，保留原 payload 并允许审核。`mid` 属于被合并源、未知嵌套引用及反向合并继续阻塞，现役 34 个数据库保护不变。

合并只整理本库记录与引用，不删除网盘文件或重放未知任务。合并逻辑验收使用隔离真实 MySQL；生产合并须有明确授权并确认同片身份，通过同一预览与保护流程执行。实际执行及跳过结果以交付记录为准。

## 部署与恢复

新增四张审核/别名/历史表及 34 个 BEFORE INSERT/UPDATE trigger。维护身份先核对原库、正常停止旧后端并完成加密 SQL/配置/镜像/状态备份，再按实际缺失定义执行两份增量 SQL。MySQL 8.0.28 不支持带 IF NOT EXISTS 的 CREATE TRIGGER，已有同名定义必须精确匹配，不能覆盖。

新别名或百度 UNKNOWN 待审进度存在后，旧消费者不能直接回退；保留在线 SQL、会话、原任务和检查点，优先兼容的前向修复。禁止用旧 dump 覆盖新增历史或删除新表作为回退。
