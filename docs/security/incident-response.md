# 安全事件响应

[当前风险](risk-register.md) · [凭据](secret-management.md) · [备份](backup-plan.md) · [完整旧模板](../history/snapshots/20261022/docs/security/incident-response.md)

这是操作预案，不能代替当前授权。先只读判断影响；隔离、停服、凭据撤销、外部通知及恢复按事件明确范围执行，保留证据/回退，不发未授权消息。

## 1. 触发条件

异常管理写入、数据/会话泄露、公开控制面、持续攻击、不可认证解密/恢复的备份。

## 2. 等级与响应

P0已确认泄露/入侵立即处置；P1重大暴露/认证失效目标1小时止血；P2单接口/未利用高危当日处理；P3低影响漂移计划修复。等级以证据确定，不据误报直接轮换/删数据。

## 3. 通用止血（Windows + Docker）

1. 记录含时区时间、主机/提交、容器ID/端口/日志摘要；完整配置与原始敏感日志只入外部受限证据区。
2. 按授权收入口/Access/Firewall、暂停相关写入方；保留容器/卷，不down-v/prune/清队列。
3. 只读check_security.py --probe、必要服务窗口日志（显式-p/-f/覆盖、脱敏），确定影响及仍有外部副作用。
4. 形成精确单服务/身份恢复方案，验证备份后实施；证据hash/归属保留。

## 4. 凭据事件矩阵

| 范围 | 顺序与验收 |
| --- | --- |
| DB/MinIO | 限入口→新scoped身份→逐消费者验证/切换→撤旧；DB实际CURRENT_USER/grants、对象公开/私有分别验 |
| JWT/internal/QQ | 新独立token/会话吊销→旧值拒绝→新链路；群出站仅获批 |
| Quark/Xunlei/微博 | provider撤旧/手动恢复、受控备份/私有写回、会话验收；不默认转存/发帖 |
| Tunnel/Access | 核对象归属、限定撤销/更换、只到loopback；管理匿名/USER/ADMIN三态 |
| Git历史 | 停传播/确认有效值/轮换；clone协调和历史重写独立批准 |

## 5. 应用层攻击

429/耗时/连接数先区分依赖和刷取，不直接提高限额。按路径/来源限流并保留最小公开可用。越权管理核设备/角色/资源/配置审计；恶意URL按provider/任务ID暂停并审核，优先软处理，不直接升级第三方源分享。

## 6. 恢复和关闭条件

原暴露面复测、相关旧凭据确认失效、数据/会话影响清楚、备份认证及适用临时恢复通过、监控覆盖原因、自动化按原状态恢复/明确关闭、日志无立即复发、状态文档记录日期/证据/待办。未满足不关闭。

## 7. 联系和记录模板

事件ID；发现时间/来源；服务/等级；授权范围；已实施止血；轮换键名；证据/检查点；验证结果；恢复/回退决定；责任人/期限。外部联系遵循当前用户明确指令。
