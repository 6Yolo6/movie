# GYING 磁力与种子采集

## 范围与解析契约

高频元数据采集只保存 P2P 链接，不下载影片或种子文件，也不创建云盘发现、转存或发布任务。

GYING 的下载响应可使用 `downlist.list` 紧凑并行数组：

- `m`：40 位 BTIH；仅处理 `k=0` 的 BT 项，跳过目录/压缩包项。
- `t`：资源标题，保存时限制 255 字符。
- `u`：稳定 BT 资源 ID，同时作为 `source_ref`。
- `hex`：上游临时下载票据；格式有效时组成 `/dbt/{u}/{hex}` 种子地址。缺少有效票据时只保存磁力链接。

磁力地址使用小写 BTIH，不把标题加入地址，避免改名造成重复。并行数组长度或身份不合法时报告错误，不能把不透明编码当作磁力哈希。

## 幂等与失败语义

- 普通链接按影片及 URL/hash 查找已有活动记录。
- 种子地址的票据会变化；URL 未命中时，按影片、GYING 来源、BT ID、TORRENT 类型、P2P provider 查找并更新同一活动记录，不恢复软删除记录。
- 新增和更新均检查持久化返回值，失败不能累计为成功。
- 资源专用 API `GET /resources/{typeCode}/{mid}` 启用严格模式：请求异常、非 200、非 JSON、上游拒绝/缺少资源结构及 BT 展开失败必须返回错误；明确的空资源数组仍是合法空结果。其他历史调用保留原有非严格回退行为。
- 任务 payload 保存 `directResourceLinks`（本批次完整完成的影片所保存/更新的链接数）和 `directResourceFailures`（P2P 失败影片数）。它们不是本批次新增行数；单片中途失败前可能已有部分写入，重试靠幂等去重。
- P2P 失败不丢弃已保存元数据，但任务标记 FAILED 并留下错误；自动范围任务不推进页码/页内位置，下次从原批次重试。元数据失败计数与 P2P 失败计数分别保留。
