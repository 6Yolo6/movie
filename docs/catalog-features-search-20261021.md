# 推荐特征、自然语言影视搜索与求职成果验收

构建与实现日期：2026-10-21；生产部署：2026-10-22 00:07–00:08，Asia/Shanghai。

本轮延续 [10 月 16 日求职补强路线](ai-career-project-analysis-20261016.md)，已将“猜你喜欢”的收藏和浏览聚合成可复用特征，并在 `/ai-assistant` 加入条件解析、简介检索、分页及资料依据。代码、合成评测、真实片库只读验证、候选镜像与生产验证分别记录。实现没有新增模型训练、embedding 或文档 RAG。

## 1. 交付能力

### 用户行为转为推荐特征

`CatalogRecommendationEngine.FeatureIndex` 按片库快照预计算稀疏影片向量，`UserFeatures` 将有效收藏与近期浏览按行为权重聚合为用户向量。收藏权重 3；90 天内浏览权重为 exp(-距今天数/30)，30 天后为初值约 36.8%，已有收藏与浏览叠加；最多读取各 100 条，收藏及已浏览影片排除于当前推荐候选。用户 ID 不进入特征向量，只用于业务鉴权及读取本人的行为。

字段权重：类型 0.50、导演 0.15、演员 0.10、分类 0.10、年代 0.05、地区 0.05、语言 0.05；类型使用 IDF，字段归一化。候选通过向量点积取得内容分，混合共同收藏 0.20、内容 0.55、评分 0.15、热度 0.10；冷启动按评分 0.75、热度 0.25。共同收藏按独立用户聚合，相同用户/影片去重，至少两个用户支持才使用。保持多样性重排及逐片理由，响应返回 `featureVersion=content-features-v2`。

特征为进程内不可变对象，不是新增持久化 Feature Store。说明理由引用本人的种子影片或片库属性，不公开其他用户身份。排序规则与旧算法有所变化，性能对比不代表结果完全等价或推荐质量提升。

### 自然语言检索

新增登录接口 `GET /api/ai/natural-search?query=&page=&size=`，与标题搜索共用每用户 30 次/分钟限流。`POST /api/ai/query` 对已识别的描述直接返回片库结果；已存在的精确片名优先保留标题搜索，多轮详情/资源追问继续使用既有助手路径。

`NaturalMovieQuery` 把已支持的年份、年份范围、近几年、类型、排除类型、最低评分、最长时长和有限主创/地区/语言表达转成固定条件。2026 年的“近几年”明确为 2022–2026 五个日历年；“高分”为片库存量评分至少 8。未知或单集/多段时长不通过最长时长过滤。实际评分取豆瓣、IMDb、TMDB 存量值最大值，不是统一评分口径。

`CatalogTextIndex` 使用 ICU 分词、加权 BM25 倒排索引及显式中英主题词表，索引片名、别名、系列名、主创、类型和简介。片名权重 4、别名/系列 3、类型/导演 2、演员 1.5、简介 1；主题词匹配的分数乘 0.65。非空文本至少覆盖 60% 查询词才进入候选，硬条件先过滤，按检索分、评分和 ID 排序。响应附真实资料片段、命中词与 `indexVersion=icu-bm25-concepts-v1`，没有生成影片记录。

片库快照最多 50,000 条、TTL 60 秒，文本索引仅在自然搜索时延迟构建；达到上限时 `catalogTruncated=true`。本轮不改数据库架构。现有片库标题、审核、删除和资源可见性规则保持使用业务查询。

检索是词法检索及有限概念扩展：如“太空探索”可能排到包含太空背景的恐怖电影，未必符合探索主题；“烧脑”的记忆/梦境映射也较宽。任意口语、否定、多个混合条件、跨语言理解尚不完整。只有 `catalog.filters` 中已识别条件会被执行，需继续补充独立题集和误召回样本。

### 网页结果

自然语言与标题结果均支持完整分页；分页失败保留原结果。展示原资料片段和理由，影片链接新标签页打开，保留原对话；中英示例加入原计划中的“找近几年偏烧脑、时长不超过两小时的科幻电影”。片库直查不依赖模型在线。

合成搜索题集包含 40 个题目，development/evaluation 各 20，每组 19 个正例和 1 个无答案例。在同一合成片库上，原标题关键词基线 Top-5 命中分别为 2/19，新检索分别为 19/19；两个无答案例均为空。题目与标签由实现时编写和检查，evaluation 仅为文件分组，**不是独立盲测或未参与调参的留出集**。零条件违规是用同一条件对象回查的程序回归断言，不是独立参数理解正确率。不能据此宣称生产语义准确率 100%。

固定推荐计算对比：同一组 2,000 个合成影片、60 个种子，预热 2 轮、采样 5 轮；冻结旧实现中位数 415.7289 ms，新特征排序 81.0494 ms，约减少 80.5%；一次特征索引构建 57.7854 ms 单独列出。此结果不包含 DB、HTTP、50,000 共同收藏读取或并发负载；执行顺序固定且样本量小，不是生产 p95/吞吐或 CTR 提升。旧算法被冻结为仅测试类 `LegacyRecommendationBaseline`。

真实生产库仅通过独立服务 fixture 只读查询：9,615 个活动影片中 9,220 有简介、8,531 有时长。原求职场景返回 1 部，2010–2020 年高分科幻排除恐怖返回 33 部，英文时间旅行/两小时返回 18 部，未知“量子海豚火山”返回 0；自然结果前三页共 21 个唯一 ID，个人/冷启动各 12 条且含理由。fixture 使用模拟鉴权、最小只读 DB 身份，不启动生产调度器。

最后一次只读 fixture 测量：在镜像复制同时运行时，首次自然查询含索引构建 14.640 秒，后续样本 31–62 ms；个人推荐 2.703 秒、冷启动 0.891 秒。首次构建仍需优化，TTL 失效后也会重建；这些数字只属于此机器/负载的一次样本，不是网站端到端 SLA。实际网站账号登录后的完整个人链路本轮未新增验证，匿名鉴权与模拟页面覆盖分别记录。

## 5. 当前可用于简历的表述

> 开发并部署影视检索与个性化推荐功能，将收藏和时间衰减浏览聚合为类型、主创、年代等稀疏特征，结合共同收藏、评分热度及多样性重排提供逐片推荐依据。
>
> 实现自然语言条件解析与 ICU/BM25 资料检索，支持年份、类型、评分和时长过滤，返回片库原文片段和分页结果；使用版本化合成题集、隔离 MySQL 与浏览器回归验证接口和结果边界。
>
> 在固定 2,000 部合成影片、60 个种子场景中，通过预计算影片特征与用户聚合，将推荐排序计算中位数从 415.7 ms 降至 81.0 ms；独立记录索引构建耗时，提供旧实现基线和可复现实验。

面试时明确算法权重是规则设定、尚未验证线上用户效果；本轮使用生成式 AI 辅助实施，但该检索路径没有依赖模型生成影片或评分。避免写“大模型训练”“生产语义准确率 100%”“推荐 CTR 提升 80%”“已完成文档 RAG/API Key 平台”。
