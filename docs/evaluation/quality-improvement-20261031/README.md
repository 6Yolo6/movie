## 因果边界与冻结材料

- 四条工具不透明记录为 h02/r2/t1、h11/r2/t1、h24/r1/t1、h24/r2/t1。trace 只证明 searchMovies 曾执行，观测 `catalog=null` 且缺原参数/结果；能确认回答和澄清不足，不能断言检索器、关键词、片库覆盖或模型幻觉就是根因。
- 自然检索仍保留原 query 文字。某个 filter 为空只证明该硬条件没有形成可核验的过滤，不能单独证明相关文字完全没有参与检索。没有候选的 `candidates` 标签表示有用候选缺口，不能据此证明排序错误或片库一定存在精确解。
- h21 首轮只说“三部 90 分钟以内的喜剧”，没有明确说电影。返回 `tv` 需要说明作品形态和时长口径，不能单凭 `tv` 判定违反了明确的电影类型限制；数量不足的处理、时长单位不清和泛词匹配仍可核对。
- 导演排除有直接元数据证据：h19 第二轮包含诺兰导演作品，h22 第二轮包含王家卫导演作品。h21 第三轮的事实矛盾可由同会话、同 ID 的前轮简介核对，不依赖已省略的来源链接。

两条部分有用回答及四次无回答任务失败不计入 82 条。无回答失败不赋质量分，也不由前轮语义问题推断失败原因。**本轮新增人工审核为 0**，模型来源保持 `reviewer.kind=model / name=Codex`；没有把用户整体反馈或模型诊断改成人工评分。

旧题、freeze、报告和原评分保持不可变；本次核对的报告、受限观测、同日 catalog 字节 hash 与历史记录一致，完整绑定在审计文件。原回答 hash 是报告和观测保存的绑定声明，未用已脱敏的文字重算来冒充原文完整验证；同日 catalog 仅作公开元数据辅助来源。10 月 25 日网站分流和结构化研究已更改，旧自然检索接口仍存在，不能把旧实现的失败直接推断成现役状态。
