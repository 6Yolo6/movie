## 诊断

原网站 88 轮中，78 轮走直接业务分流，只有 10 轮到模型，4 轮失败。单个“推荐”优先覆盖复杂条件，否定人物被拆词误召回；旧直接路径不继承历史，空结果不升级。原轨迹 searchMovieWeb 调用为 0，百科请求能联网不代表已经全网搜索。历史失败错误码丢失，因此不能断言四次失败同因。

同一 10,432 条公开元数据快照复现旧检索。来源、地区/语言、缺失评分与时长、简繁别名也会导致检索失败。真实 1.7B 条件抽取会猜片名/年份，反转人物排除；扩大为普通 4B 仍会遗漏实体和误判剧情。因此需要修分流、原文/片库核验、检索与模型，而不是只替换一个模型。

## 实现边界

- 仅明确已知片名和简单泛推荐直返；复杂中文进入结构化查询计划，不生成 SQL、URL、用户身份或执行动作。
- 片库确定性执行分类、人物/排除、范围、评分来源和排序；从原文补回真实人物字典中的遗漏，完整姓名优先于其中的短姓氏；原文能确定完整姓名时收窄模型的局部人名，唯一别名/小错可消歧，无法确认时说明。
- 序号与上一轮结果由服务端当前用户、有效任务、候选顺序和租约决定。翻页保存新的候选上下文，失败轮不进入后续历史。
- BM25 与 BGE-M3 候选融合，活库 ID 和内容 fingerprint 过滤过期向量；模型按核心主题允许细节近似，用实际简介片段核对相关性，候选数和“可能符合”分别说明。
- 搜索访问固定 Bing 搜索页面，解析有界 HTML、域白名单与实际搜索结果，保留来源/查询时间；不访问模型生成 URL，不把搜到链接称为当次逐页验证。
- 模型输出长度/上下文有界，失败保留错误码和调用轨迹。候选和搜索资料作为数据，不作为系统指令。
