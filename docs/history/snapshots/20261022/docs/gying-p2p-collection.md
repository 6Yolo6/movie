# GYING 磁力与种子采集

## 范围与解析契约

高频元数据采集保存磁力和可公开使用的种子链接；**不将 GYING `/dbt/…` 账号下载地址存入正式资源库**，无论是否附带临时票据或使用镜像域名。独立小文件归档队列将选中的磁力文本、真实 torrent 元数据上传到对应影片网盘目录。两条链路均不下载视频，不运行 BT/网盘离线下载，不创建历史视频发现或转存任务。归档契约见 [磁力与种子网盘归档](p2p-cloud-archive.md)。

GYING 的下载响应可使用 `downlist.list` 紧凑并行数组：

- `m`：40 位 BTIH；仅处理 `k=0` 的 BT 项，跳过目录/压缩包项。
- `t`：资源标题，保存时限制 255 字符。
- `u`：稳定 BT 资源 ID，同时作为 `source_ref`。
- `hex`：上游临时下载票据，仅在 source 内存中用于下载真实 `.torrent` 文件。`/dbt/{u}`、`/dbt/{u}/{hex}` 均不是可交给普通用户的下载链接。外发资源列表移除这些地址，在对应磁力上附带 `archive_torrent=true`；同一 BT 版本的中文字幕证据保留。缺少有效票据时只保存磁力。

磁力地址使用小写 BTIH，不把标题加入地址，避免改名造成重复。并行数组长度或身份不合法时报告错误，不能把不透明编码当作磁力哈希。

## 选择与幂等

- 每片只选 1080P、4K（2160p）各一个当前版本，同版本磁力与 torrent 为一组。优先明确中文字幕，最终至少一份；国语、配音不算字幕，没有合格版本就跳过，不编造清晰度或字幕。
- 普通链接按影片及 URL/hash 查找；公开 torrent 镜像可按稳定 BT ID 原位更新。GYING 账号下载地址不新增、不刷新为公开资源，票据轮换只影响内部取文件。
- 新版本可原位更新同分辨率的自动采集槽位，不批量删除历史多余行或网盘文件；软删除记录不恢复。
- 所选公开链接全部持久化成功后才创建 `P2P_ARCHIVE` 任务。v2 的 `resourceIds` 只引用真实保存的资源，`torrentMagnetIds` 指向需要归档种子的磁力记录；任务不保存账号下载 URL 或票据。任务按影片、provider、稳定版本指纹去重，保持与旧磁力/种子组合相同的指纹。
- 公开影片详情、每日推荐和网页资源搜索过滤历史 `/dbt/…` 链接；原数据库记录不删除，旧 v1 任务继续按原 ID 读取。磁力及 `GYING_P2P_ARCHIVE` 的自有网盘分享仍可见。旧磁力槽位被新 BT 替换时，旧归档任务先按指纹判断为 `CANCELED`，不因旧种子行尚未更新而不断重试。

## 失败语义

- 资源专用 API `GET /resources/{typeCode}/{mid}` 为严格模式：请求异常、非 200、非 JSON、上游拒绝/缺少资源结构和 BT 展开失败返回错误；明确空数组仍合法。
- 元数据任务 payload 的 `directResourceLinks` 是完整完成影片的保存/更新次数，不是新增行数；`directResourceFailures` 是 P2P 失败影片数。
- P2P 失败保留已保存元数据，但任务失败、范围位置不推进；原批次重试靠幂等去重。
- 网盘归档与元数据任务分别审计。源站或上传请求失败保留检查点，退避 30 分钟、最多 3 次；只有全部文件确认并得到自有分享后才写入网盘归档资源，不以排队或 HTTP 200 冒充上传成功。
