## 阅读与维护约定

- **现状**只以[当前状态](current-project-status.md)及其引用的带日期证据为准；未在本轮复核的旧证据保留原日期。
- **契约与流程**在 API、数据库、开发、部署和发布文档各维护一份；不要在多处复制完整命令或状态表。
- **历史**保留结果、回滚位置、适用时点及未覆盖范围。旧报告中的“当前”“已通过”只属于当次记录。
- **目标配置 ≠ 线上事实**；脚本检查通过、隔离候选启动或 HTTP 200 都不能单独证明业务成功。
- 仓库外路径只是交接线索，不是仓库自带文件；执行前要验证其存在、权限、内容及适用版本。忽略目录中的临时证据也不保证随 Git 克隆取得。
- 只记录配置键名和脱敏摘要，不提交真实环境文件、完整 Docker inspect、Cookie、Token 或备份私钥。
- 改动文档后检查相对链接、代码围栏、迁移文件清单及暂存区差异；纯排版/归档不刷新运行态验收日期。
