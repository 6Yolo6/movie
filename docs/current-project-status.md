# 当前项目状态

更新时间：2026-08-05

本文件只记录当前能力、长期约束和仍需处理的工作。历史验证样例、一次性资源 ID、临时调试过程不在此保留；具体接口和部署参数分别以 `docs/api.md`、`docs/deployment.md` 为准。

## 当前目标

- 维护电影、剧集、动漫片库及用户提交资源。
- 通过 TMDB、PanSou/Panso API、quark-auto-save 和 GYING 自动补全元数据与网盘资源。
- 支持 QQ 群资源查询、两个独立腾讯频道账号和新浪微博资源帖，并保留可审计记录。
- 所有清理和修复保持幂等、可追踪，核心影片和资源只做软删除。

## 运行架构

- 对外入口：nginx `80/443`，反向代理 Next.js 前端和 Spring Boot 后端。
- 核心服务：`frontend`、`backend`、`gying-source`。
- 数据依赖：MySQL、Redis、MinIO；资源搜索和转存连接现有 PanSou、quark-auto-save 服务。
- QQ 集成：NapCat/官方 QQBot 用于群聊；宿主机 `tencent-channel-cli` 保留原频道账号，独立 `social-publisher` 容器承载第二 QQ 账号和新浪微博。
- 生产容器和 JVM 使用 `Asia/Shanghai`。

## 已具备能力

### 片库与治理

- 片库分页、分类筛选、详情、收藏热门、评论留言和站内通知。
- 用户可提交、编辑和软删除网盘/磁力/种子/在线播放资源。
- 管理端支持资源审核、批量审核、举报处理、失效标记、评论和用户管理。
- 管理员编辑资源时，URL 未变化可正常保存其他字段；只有改成另一条活动资源的 URL 时才提示重复。
- `movie_metadata` 与 `resource_link` 使用 `deleted_at` 记录软删除；历史关系不物理删除。
- 重复 TMDB 影片和标题污染资源提供 dry-run 后清理，优先保留现有片库 canonical 记录。

### 影视资源中心

- TMDB 热门/高分采集会匹配现有影片，避免覆盖站内收藏热度或创建重复剧集。
- TMDB 自动采集按配置间隔每次轮询一个来源，多个来源分散到全天执行；活动任务存在时不会重复入队。
- 资源中心看板显示 TMDB 影片总数、近 24 小时同步/新增/失败任务、资源发现和入库统计，并显示最近与下次采集时间。
- 资源搜索同时合并本地 PanSou 与外部 Panso API，按 URL 去重。
- 自动资源必须先转存到自有夸克目录并创建自有分享，之后才能写入 `resource_link`。
- 发现结果支持标题/影片 ID/链接筛选、时间排序、可点击来源/自有分享和复选批量操作。
- 空目录或分享失败先重跑原转存，仍失败时重新搜索、转存和发布。
- “缺资源影片”按实际可用 `DISK` 链接口径检查，可选择 GYING 或 PanSou 补全。
- 缺资源补全会按候选逐条转存，带年份失败后改用纯片名继续搜索；只有活动资源真正写入后才返回成功，GYING 会优先复用来源身份并自动扫描目录定位，仍失败时回退 PanSou。
- 缺资源列表支持跨页勾选并批量从 GYING 或 PanSou 补全，每批最多 20 部；后端按影片记录逐条成功/失败结果，超限时明确提示而不静默截断。
- 发现状态可用 dry-run 预览后校准历史标题误判、旧任务冲突和发现/转存状态不一致；真正不相关标题及季号冲突仍保持忽略。
- 重试分享会为没有任务或任务已取消的发现重建转存任务；没有生成自有分享及活动正常网盘资源时明确返回失败，不再以“跳过”冒充完成。
- TMDB 剧集记录会补全系列名和目标季；转存多季合集时先递归定位明确的目标季目录并收窄分享 `fid`，再写入独立季目录，找不到对应季时改试下一候选。
- 电影合集会按中文名、英文名和年份递归定位明确的单片目录；命中后只递归转存该目录，不把整套合集写入目标影片目录。
- TMDB 同步失败不会再显示为采集成功；网络线路可通过 `TMDB_API_BASE_URL` 调整。

### GYING 数据源

- `gying-source` 支持最近更新、单片采集、预告片补全、本人已发布资源检查和批量修复。
- 管理页支持按电影、剧集、动漫浏览 GYING 高分/最新/热度目录，并可按页批量确保资源。
- `movie_source_identity` 以来源、类型、外部 ID 和季号连接 TMDB、GYING 与本地 canonical 影片；自动关联只接受严格片名、类型及年份/季号等元数据锚点。
- 剧集可一键补齐其余季；历史 TMDB 影片缺少 GYING 身份时，先扫描片库目录严格定位并建立身份，再处理各季资源。
- 单片与批量缺海报修复优先重新请求 TMDB 海报，TMDB 不可用时再按已确认或严格发现的 GYING 身份回补。
- GYING 影片 ID 与本地 canonical 影片 ID 分离，支持资源写回已有 `tmdb_*` 或片库记录。
- 本地无资源时可验证并尝试最多 5 个 GYING 夸克候选，成功转存后发布自有链接。
- 失效资源优先复用 `saved_path` 重分享，失败时改用同片其他候选，并保留原 GYING `panlist.id`。
- 共享站点 Session 有锁保护，并处理 PoW、登录过期和 AJAX JSON/HTML 响应差异。
- 管理页可切换当前 GYING 用户名、密码、Cookie 和发布者显示名；凭据不回显、不入库，容器重启后恢复环境变量默认值。

### QQ 自动化

- QQ 群查询先精确匹配本地影片和已发布资源，缺失时才进入 TMDB、搜索、转存、分享和发布链路；每次资源结果必须先验证并附带至少一条自有夸克分享。
- 用户可在 5 分钟上下文中选择影片、网盘类型和返回数量；指定百度等其他网盘时，自有夸克仍保留在首位，其他网盘作为追加结果且不写入正式资源。
- 带季数搜索会严格命中对应季；同样健康且覆盖整季/全集时，优先管理员或用户明确投稿的自我分享，再使用自动转存链接。
- 群内直回消息会 @ 发起用户；未知或空 AT 消息返回使用帮助。OpenClaw 补丁通过 `qrcode` 为回复中的夸克分享生成二维码图片。
- `/admin/automation` 管理搜索日志、频道发帖日志和自动化配置。
- QQ 搜索看板统计搜索总量、近 24 小时搜索、成功率、无结果和需处理记录。
- 资源中心手动发 QQ 通过受内部令牌保护的宿主机桥接立即执行；失败时保留 `PENDING` 供定时任务处理。
- 频道帖子模板支持 `{{title}}`、`{{year}}`、`{{type}}`、`{{link}}`、`{{intro}}`；自动候选按站内热度、TMDB 热度和资源录入时间排序，同一影片只取一条。
- 频道帖子使用 UTF-8 内容文件、可点击资源链接和影片海报，并用全局互斥锁避免并发发帖。
- 本地和 TMDB 都无法精确命中时，机器人优先调用 GYING 搜索并展示带来源的候选列表；用户回复序号后才按候选来源身份采集和转存，失败再回退本地 PanSou 与外部 Panso API。

### 多平台发布

- `/admin/automation` 增加“多平台发布”页签，维护 4 个第二 QQ 账号频道目标和 1 个新浪微博目标；支持添加已授权账号下的新频道/平台目标。
- 支持单目标一键发下一条、全部目标批量发布、每日定时、每次条数、间隔和正文模板。
- 页面展示分页发布记录，可按平台和状态筛选，查看外部帖子地址、失败原因并重试失败记录。
- 候选按站内热度、TMDB 热度和资源录入时间排序；同一目标按影片去重，不因资源链接更新重复发同片。
- 第二 QQ 和微博凭据分别保存在独立容器卷，不覆盖原 QQ 机器人或宿主机频道账号。
- 发布日志记录 `PENDING`、`POSTED`、`FAILED`、外部帖子地址和失败原因；两个平台未授权时只影响对应独立目标。
- 2026-08-05 已通过独立第二 QQ 账号真实发布并写回外部帖子地址；新浪微博仍待设备授权。

## 配置与安全

- 密钥、Cookie、密码、Token 只放 `.env`、外部服务配置或进程内存，不提交到 Git。
- Resource Hub 和 QQ 自动化的非敏感运行参数保存在 `sys_config`。
- 数据库新增表和字段默认使用中文 `COMMENT`。
- 外部结果必须通过标题相关性、链接状态和重复检查后才能发布。
- 不重复启动已有 Redis、PanSou、quark-auto-save 或 MinIO 容器；生产 compose 默认连接现有依赖。

- 用计划保留的真实影片再做一次 TMDB -> 搜索 -> 转存 -> 分享 -> 入库 -> QQ 回发全链路验收。
- 豆瓣评分暂无可靠官方 API，不作为稳定生产能力。

## 长期不变量

- `movie_metadata` 是影视主表，`resource_link` 是可用资源链接表。
- `movie_metadata.popularity` 只表示站内收藏热度；TMDB 热度使用独立字段。
- 自动采集只在拥有可用自有分享后发布，不能把第三方夸克源链接直接写成正式资源。
- 本地模糊匹配只能提供候选，不能直接触发转存或回复。
- 失效修复原位更新原资源；临时新资源成功后应归并，避免同片多条活动自有分享。
- 删除核心数据、重复清理和标题匹配不确定时先 dry-run，不执行物理删除。
