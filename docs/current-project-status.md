## 当前目标

- 维护电影、剧集、动漫片库及用户提交资源。
- 通过 TMDB、PanSou/Panso API、quark-auto-save 和 GYING 自动补全元数据与网盘资源。
- 支持 QQ 群资源查询、两个独立腾讯频道账号和新浪微博资源帖，并保留可审计记录。
- 所有清理和修复保持幂等、可追踪，核心影片和资源只做软删除。

## 运行架构

- 对外入口：nginx `80/443`，反向代理 Next.js 前端和 Spring Boot 后端。
- 核心服务：`frontend`、`backend`、`gying-source`。
- 数据依赖：MySQL、Redis、MinIO；资源搜索和转存连接现有 PanSou、quark-auto-save 服务。
- QQ 集成：NapCat/官方 QQBot 用于群聊；宿主机 `tencent-channel-cli` 保留原频道账号，独立 `social-publisher` 容器承载第二 QQ 账号和新浪微博。
- 生产容器和 JVM 使用 `Asia/Shanghai`。
- 微博网页会话通过 social-publisher 独立持久化浏览器会话支持管理员扫码更新，会话文件只保存在运行时卷。

## 已具备能力

### 片库与治理

- 片库分页、分类筛选、详情、收藏热门、评论留言和站内通知。
- 用户可提交、编辑和软删除网盘/磁力/种子/在线播放资源。
- 管理端支持资源审核、批量审核、举报处理、失效标记、评论和用户管理。
- 管理员编辑资源时，URL 未变化可正常保存其他字段；只有改成另一条活动资源的 URL 时才提示重复。
- `movie_metadata` 与 `resource_link` 使用 `deleted_at` 记录软删除；历史关系不物理删除。
- 重复 TMDB 影片和标题污染资源提供 dry-run 后清理，优先保留现有片库 canonical 记录。

### 影视资源中心

- TMDB 热门/高分采集会匹配现有影片，避免覆盖站内收藏热度或创建重复剧集。
- TMDB 自动采集按配置间隔每次轮询一个来源，多个来源分散到全天执行；活动任务存在时不会重复入队。
- 资源中心看板显示 TMDB 影片总数、近 24 小时同步/新增/失败任务、资源发现和入库统计，并显示最近与下次采集时间。
- 资源搜索同时合并本地 PanSou 与外部 Panso API，按 URL 去重。
- 自动资源必须先转存到自有夸克或迅雷目录并创建自有分享，之后才能写入 `resource_link`。
- PanSou 与 GYING 已识别迅雷候选并创建独立 `xunlei_transfer_task`；迅雷 runner 优先于历史夸克积压执行，支持受 internal token 保护的指定任务重试。
- PanSou 的迅雷链接健康结果只作为提示，不再因 `bad` 直接忽略候选；链接是否可用由官方迅雷转存 API 最终判定。夸克候选仍保留发现阶段的失效拦截。
- 迅雷任务从失败恢复为成功时会显式清空旧 `last_error`，避免管理页同时显示成功状态和过期错误。
- 迅雷转存与公开分享已完成真实链路验证；生产 `XUNLEI_SHARE_ENABLED=true`，没有自有分享时发布器仍禁止回退写入第三方迅雷源链接。
- 迅雷分享响应兼容顶层、`data`、`share` 和 `data.share` 下的 URL/提取码字段；分享接口未返回自有 URL 时任务明确计为失败，不再以“已提交”或“成功但无链接”继续发布。
- 迅雷公开分享根目录使用 `/share`，子目录遍历使用 `/share/detail`；`pass_code_token` 和 `page_token` 按网页响应作为不透明值原样保留，并在 URI 中只做一次百分号编码，不再强制转换 base64/base64url。目录遍历失败且尚未发现视频时会透传真实迅雷错误，不再误报“contains no video files”。
- 迅雷公开分享读取不发送账户 Authorization；restore、文件列表和自有分享创建仍要求账户 Authorization。restore 递归筛选源分享中的视频文件 ID，只转存视频，不连带广告图片、文档或整个顶层目录；自动失败任务最多尝试 3 次，手工指定任务重试允许越过该上限。
- “发现结果”的重试分享与发布按 provider 分流：迅雷记录调用迅雷 runner，夸克记录调用 quark runner，避免迅雷链接误送至 quark-auto-save。
- 迅雷分享文件解析兼容真实 API 的 `file_id`/`fid`、`filename`、`items`、camelCase MIME/扩展名等字段，并可从文件名后缀识别视频，避免链接内有视频却误报“contains no video files”。
- `AUTO` 发现会检查 GYING 已返回的 provider：只有夸克时补搜迅雷，只有迅雷时补搜夸克；QQ 资源列表会同时读取系统自有夸克、迅雷和待选择的发现结果，不再因单一 provider 先命中而跳过另一种网盘。
- 发现结果支持标题/影片 ID/链接筛选、时间排序、可点击来源/自有分享和复选批量操作。
- 空目录或分享失败先重跑原转存，仍失败时重新搜索、转存和发布。
- “缺资源影片”按实际可用 `DISK` 链接口径检查，可选择 GYING 或 PanSou 补全。
- 缺资源补全会按候选逐条转存，带年份失败后改用纯片名继续搜索；只有活动资源真正写入后才返回成功，GYING 会优先复用来源身份并自动扫描目录定位，仍失败时回退 PanSou。
- 缺资源列表支持跨页勾选并批量从 GYING 或 PanSou 补全，每批最多 20 部；后端按影片记录逐条成功/失败结果，超限时明确提示而不静默截断。
- 发现状态可用 dry-run 预览后校准历史标题误判、旧任务冲突和发现/转存状态不一致；真正不相关标题及季号冲突仍保持忽略。
- 重试分享会为没有任务或任务已取消的发现重建转存任务；没有生成自有分享及活动正常网盘资源时明确返回失败，不再以“跳过”冒充完成。
- TMDB 剧集记录会补全系列名和目标季；转存多季合集时先递归定位明确的目标季目录并收窄分享 `fid`，再写入独立季目录，找不到对应季时改试下一候选。
- 第 1 季夸克来源在没有显式季目录时，会在无冲突季标记且根目录直接含视频或仅含一个有视频的无标记目录时使用根目录/该目录；多季冲突仍拒绝。
- 电影合集会按中文名、英文名和年份递归定位明确的单片目录；命中后只递归转存该目录，不把整套合集写入目标影片目录。
- TMDB 同步失败不会再显示为采集成功；网络线路可通过 `TMDB_API_BASE_URL` 调整。
- TMDB 客户端按最小请求间隔访问，并对 429、5xx 和连接超时做有限重试；当前生产失败样例主要是外部网络连接超时，不是数据库认证失败。
- 自动资源发现使用 `AUTO` 路由时先做 GYING 精准身份与资源搜索，只有 GYING 无严格结果或转存失败才进入 PanSou；GYING 转存失败会在 24 小时内去重排入 PanSou 兜底任务。
- PanSou 明显无关的上游结果不再逐条写入“已忽略”，只保留有效链接的审计记录；历史 `Resource title does not match movie title` 记录保留，不执行物理删除。

### GYING 数据源

- `gying-source` 支持最近更新、单片采集、预告片补全、本人已发布资源检查和批量修复。
- 管理页支持按电影、剧集、动漫浏览 GYING 高分/最新/热度目录，并可按页批量确保资源。
- `movie_source_identity` 以来源、类型、外部 ID 和季号连接 TMDB、GYING 与本地 canonical 影片；自动关联只接受严格片名、类型及年份/季号等元数据锚点。
- 剧集可一键补齐其余季；历史 TMDB 影片缺少 GYING 身份时，先扫描片库目录严格定位并建立身份，再处理各季资源。
- 单片与批量缺海报修复优先重新请求 TMDB 海报，TMDB 不可用时再按已确认或严格发现的 GYING 身份回补。
- GYING 影片 ID 与本地 canonical 影片 ID 分离，支持资源写回已有 `tmdb_*` 或片库记录。
- 本地无资源时可验证并尝试最多 5 个 GYING 夸克候选，成功转存后发布自有链接。
- 失效资源优先复用 `saved_path` 重分享，失败时改用同片其他候选，并保留原 GYING `panlist.id`。
- 共享站点 Session 有锁保护，并处理 PoW、登录过期和 AJAX JSON/HTML 响应差异。
- GYING 搜索参数已按站点分类约定映射：`0` 为全部、`1` 为电影、`2` 为剧集、`3` 为动漫；普通候选使用适中模式，自动身份绑定使用精准模式，并限制模式值为 `1..3`。
- GYING 定时目录采集成功后会为本地影片排入 `AUTO` 资源发现任务，沿用 GYING 优先、PanSou 兜底、夸克转存、自有分享和正式入库流程；已有可用资源或冷却期内任务会跳过。
- 管理页可切换当前 GYING 用户名、密码、Cookie 和发布者显示名；凭据不回显、不入库，容器重启后恢复环境变量默认值。
- GYING 网盘发布使用固定 `POST /res/pan/add`，通过 `binds[0][dir]` 与 `binds[0][id]` 绑定影片；旧的路径参数形式会被上游返回 404。
- GYING 管理页“最近更新”支持勾选后批量确保资源并发布；“已发布资源健康”支持输入一个或多个 GYING `panlist.id` 定向修复，最多 100 个，未找到和 `UNCLEAR` 资源不会被修改。
- 单片“确保资源并发布”会先合并详情页资源与当前账号内容列表；只要当前账号已经发布过该影片，就不会再次调用新增接口。有效资源返回已发布，明确失效返回需到“已发布资源健康”原位修复，无法确认时要求先做健康检查。
- “已发布资源健康”现支持影片键 `tv/dlvj`、`mv/xxx`、`ac/xxx`；影片级一键操作会按 provider 分流：失效夸克原位修复，同时在缺少自有迅雷时转存并发布迅雷，不再要求用户拆成两个入口操作。原有 `panlist.id` 输入仍兼容。
- 迅雷影片级补齐会优先保留迅雷候选并交由官方 Drive API 校验，不再被夸克候选数量或 PanSou 健康结果提前截断；历史发现记录的独立提取码会自动并入迅雷 URL，修复/重试时兼容缺少 `pwd` 的旧任务。迅雷候选全部失败时返回 `FAILED/PARTIAL`、尝试次数和逐候选错误，不再静默显示为跳过。

### QQ 自动化

- QQ 群查询先精确匹配本地影片和已发布资源，缺失时才进入 TMDB、搜索、转存、分享和发布链路；每次资源结果只返回已验证的系统自有夸克或迅雷分享。
- QQ 群查询采用两阶段候选：先返回影片候选，用户选定影片后返回资源名称/画质候选；只有回复单个资源序号才创建并执行对应的夸克或迅雷转存任务。可用“夸克”或“迅雷”筛选，`夸克10` 等数量指令只展示候选，不会批量创建重复任务。
- QQ 即时发现使用延迟转存；搜索阶段不创建夸克/迅雷任务，选定资源后只执行对应提供方。OpenClaw 收到搜索指令（含无空格“搜片名/找片名”）后先发送“正在搜索资源，请稍后...”，候选最多 10 条且夸克优先；资源候选与最终分享回复均展示片名、年份、类型、地区、TMDB 评分和简介。所选分享失效时统一回复“该分享已失效，不可访问”，并保留候选上下文，用户可继续选择其他序号；无资源、无视频文件或违规/平台拦截也不会强制重新搜索。
- quark-auto-save 生产任务已完成剧集/动漫自动追更迁移：432 个正常 GYing 任务设置为每周一 `runweek: [1]`，2 个禁用任务和 3 个 `shareurl_ban` 任务保持原样；首次转存仍可由 Resource Hub 手动立即执行。
- 带季数搜索会严格命中对应季；同样健康且覆盖整季/全集时，优先管理员或用户明确投稿的自我分享，再使用自动转存链接。
- 群内直回消息会 @ 发起用户；未知或空 AT 消息返回使用帮助。OpenClaw 补丁通过 `qrcode` 为回复中的夸克分享生成二维码图片。
- `/admin/automation` 管理搜索日志、频道发帖日志和自动化配置。
- QQ 搜索看板统计搜索总量、近 24 小时搜索、成功率、无结果和需处理记录。
- QQ 资源候选遇到失效的夸克自有分享时，会清空旧分享并重新执行原夸克 URL 的转存与自有分享创建，成功后原位回写影片资源；夸克来源为 `RESOURCE_HUB`、`GYING` 或 `GYING_PUBLISHED` 的自有链接均适用。
- 资源中心手动发 QQ 通过受内部令牌保护的宿主机桥接立即执行；失败时保留 `PENDING` 供定时任务处理。
- 频道帖子模板支持 `{{title}}`、`{{year}}`、`{{type}}`、`{{link}}`、`{{intro}}`；自动候选按站内热度、TMDB 热度和资源录入时间排序，同一影片只取一条。
- 频道帖子使用 UTF-8 内容文件、可点击资源链接和影片海报，并用全局互斥锁避免并发发帖。
- 本地和 TMDB 都无法精确命中时，机器人优先调用 GYING 搜索并展示带来源的影片候选；用户回复影片序号后只导入元数据，再展示资源名称/画质候选。用户确认资源后才按候选来源身份转存，失败再回退本地 PanSou 与外部 Panso API。

### 多平台发布

- `/admin/automation` 增加“多平台发布”页签，维护多个 QQ 账号频道目标和 1 个新浪微博目标；QQ 可在页面新增账号、生成二维码扫码授权和移除账号。
- 发布目标可在管理页单独删除；删除配置前会终止该目标仍在等待的任务，已发布和失败历史日志继续保留，已删除目标的历史记录不再提供无效重试。
- 支持单目标一键发下一条、全部目标批量发布、每日定时、每次条数、间隔和正文模板。
- 页面展示分页发布记录，可按平台和状态筛选，查看外部帖子地址、失败原因并重试失败记录。
- 候选按站内热度、TMDB 热度和资源录入时间排序；同一目标按影片去重，不因资源链接更新重复发同片。
- 每个 QQ 发布账号使用独立凭据目录并保存在专用容器卷；微博使用独立发布容器的网页会话环境变量，不覆盖原 QQ 机器人或宿主机频道账号。
- 发布日志记录 `PENDING`、`POSTED`、`FAILED`、外部帖子地址和失败原因；两个平台未授权时只影响对应独立目标。
- 2026-08-05 已通过独立第二 QQ 账号真实发布并写回外部帖子地址；2026-08-06 已用微博网页会话手动发布测试微博，项目发布器已切换为网页表单请求，不再依赖官方 CLI 套餐。

## 配置与安全

- 密钥、Cookie、密码、Token 只放 `.env`、外部服务配置或进程内存，不提交到 Git。
- Resource Hub 和 QQ 自动化的非敏感运行参数保存在 `sys_config`。
- Resource Hub 管理页可在迅雷 Authorization 或 CAPTCHA Token 过期后直接更新当前后端进程内的凭据；接口只返回是否已配置，不回显或入库敏感值，容器重启后仍以 `.env` 为默认来源。
- Resource Hub 迅雷凭据卡片会从当前 Authorization JWT 的 `exp` 声明显示本地过期时间，并明确标记已过期状态；非 JWT 或无 `exp` 的凭据不推断过期时间。
- 迅雷 Authorization 当前是短时 OIDC access token，项目只保存运行时 access token，没有 refresh token 或官方设备续期凭据；浏览器网页登录 Cookie/Session 不等于 Drive API Bearer token，Resource Hub 也不会读取浏览器 Cookie、存储或请求头自动导入凭据。收到 401 时必须取得新的 Authorization 并在 Resource Hub 页面更新；代码不会尝试猜测或伪造续期接口。
